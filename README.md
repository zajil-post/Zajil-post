# منصة زاجل للنشر

واجهة عربية RTL لأسعار العملات السودانية، وحالة بعض الخدمات المصرفية، والأسئلة الشائعة. المشروع واجهة ثابتة مع وظيفة خادم وسيط على Vercel؛ لا تضع أسرار التخزين أو كلمة مرور الإدارة داخل ملفات الواجهة.

## المتطلبات

- حساب GitHub مرتبط بمشروع Vercel.
- Node.js حديث وVercel CLI للتشغيل المحلي.
- متغيرات البيئة الموضحة أدناه.
- حساب Pantry ومُعرّف Pantry صالح للتخزين السحابي.

## التشغيل محليًا

1. استنسخ المستودع وثبّت Vercel CLI إذا لم يكن مثبتًا: `npm install --global vercel`.
2. اربط المجلد بمشروع Vercel: `vercel link`.
3. أضف متغيرات البيئة إلى إعدادات المشروع أو ملف `.env.local` محلي غير مرفوع إلى Git.
4. شغّل `vercel dev` وافتح العنوان الذي يعرضه CLI.

المشروع لا يحتاج حاليًا إلى `package.json` أو حزم npm لتشغيل الواجهة. وظيفة API تستخدم وحدات Node المدمجة وواجهة `fetch`.

## إعدادات البيئة

| المتغير | مطلوب | الاستخدام |
| --- | --- | --- |
| `PANTRY_ID` | نعم للتخزين | معرّف Pantry المستخدم في التخزين السحابي. |
| `ADMIN_PASS` | نعم لتسجيل دخول الإدارة | كلمة مرور الإدارة؛ لا تستخدم كلمة مرور شخصية أو ضعيفة. |
| `ADMIN_TOKEN_SECRET` | نعم لتسجيل دخول الإدارة | سر توقيع الرموز، بطول 32 محرفًا على الأقل، ويفضّل أن يكون عشوائيًا قويًا. |

أنشئ سرًا عشوائيًا محليًا مثلًا باستخدام `openssl rand -hex 32`، ثم احفظ الناتج في إعدادات البيئة في Vercel. لا ترسل الأسرار إلى المتصفح، ولا تضعها في `app.js` أو `index.html` أو المستودع.

## إعداد PROXY_ENDPOINT

في `app.js`، القيمة الحالية هي:

```js
const PROXY_ENDPOINT = "/api/zajil";
```

هذا المسار يطابق دالة Vercel الموجودة في `api/zajil.js`. اتركه كما هو في النشر الحالي. إذا نقلت الخادم إلى مسار مختلف، غيّر القيمة إلى مسار من نفس النطاق أو إلى عنوان HTTPS موثوق، وراجع سياسة `connect-src` في CSP قبل النشر. لا توجّه الواجهة مباشرةً إلى Pantry ولا تضع `PANTRY_ID` أو أسرار الإدارة في الواجهة.

## واجهة API

المواصفات الرسمية بصيغة OpenAPI موجودة في [openapi.yaml](./openapi.yaml). جميع المسارات أدناه تحت `/api/zajil`.

### قراءة البيانات العامة

```http
GET /api/zajil?bucket=zajil_live
```

يعيد محتوى سلة البيانات العامة من Pantry. شكل الحقول يتبع بيانات زاجل المحفوظة حاليًا؛ لا تفترض حقولًا إضافية غير الموجودة في البيانات.

### تسجيل دخول الإدارة

```http
POST /api/zajil?action=login
Content-Type: application/json

{"password":"YOUR_ADMIN_PASSWORD"}
```

استجابة ناجحة:

```json
{"token":"<signed-token>","expiresIn":28800}
```

أرسل الرمز بعد ذلك في ترويسة `Authorization: Bearer <token>` عند إجراء عمليات الإدارة. مدة الرمز ثماني ساعات.

### إرسال سؤال عام

```http
POST /api/zajil?action=submit_question&bucket=zajil_inbox
Content-Type: application/json

{"sender":"متابع زاجل","text":"كيف أستخدم الخدمة؟","time":"10:30 م"}
```

تقبل الواجهة اسمًا اختياريًا حتى 60 حرفًا، ونص سؤال بين 4 و500 حرف، ووقتًا حتى 40 حرفًا. تُطبّق الدالة حدًا تقريبيًا للطلبات العامة في الذاكرة؛ لا تعتمد عليه وحده كحماية إنتاجية ضد الإغراق.

### تسجيل زيارة

```http
POST /api/zajil?action=visit&bucket=zajil_inbox
Content-Type: application/json

{}
```

تزيد عدّاد الزيارات المحفوظ في سلة الوارد.

### عمليات الإدارة

- قراءة الوارد: `GET /api/zajil?bucket=zajil_inbox` مع رمز الإدارة.
- تحديث البيانات العامة: `POST /api/zajil?bucket=zajil_live` مع رمز الإدارة وجسم JSON الذي يمثل حالة البيانات كاملة.
- الكتابة إلى سلة الوارد غير متاحة للعامة. لا ترسل رمز الإدارة إلى واجهة عامة أو سجلات المتصفح.

الرموز المتوقعة للأخطاء تشمل `400` للمدخلات غير الصحيحة، و`401` لبيانات الدخول غير الصحيحة، و`403` لعملية غير مصرّح بها، و`405` لطريقة غير مدعومة، و`429` عند تجاوز حد الطلبات، و`502/503` عند تعذّر التخزين أو عدم اكتمال الإعداد.

## ملاحظات الأمان

- تستخدم الصفحة سياسة CSP تمنع JavaScript المضمّن في سمات HTML. بقيت `'unsafe-eval'` في `script-src` لأن Tailwind Play CDN قد يحتاجها؛ الأفضل لاحقًا بناء CSS محلي وإزالة اعتماد التشغيل على CDN، ثم حذف هذا الاستثناء.
- بقي `'unsafe-inline'` في `style-src` بسبب التنسيقات الحالية؛ لا يعني ذلك السماح بمعالجات JavaScript المضمّنة.
- لا تُضاف SRI إلى الموارد الخارجية إلا بعد التحقق من قيمة التجزئة الفعلية لكل ملف ثابت. موارد الخطوط الديناميكية لا يناسبها تثبيت تجزئة CSS عامة.
- واجهة API تعمل من نفس النطاق ولا تحتاج CORS مفتوحًا. لا تضف `Access-Control-Allow-Origin: *` دون سبب محدد.
- حد الطلبات الحالي محفوظ في ذاكرة العملية، وقد لا يكون ثابتًا بين مثيلات Vercel؛ كما أن عنوان العميل يجب ألا يُوثق من ترويسات قابلة للتزوير دون تحقق من منصة الاستضافة. استخدم حماية/تحديد معدل على مستوى المنصة عند الحاجة.
- احتفظ بالأسرار في إعدادات Vercel، واستخدم HTTPS، وراجع سجلات النشر بعد أي تعديل أمني.

## الفحوصات

تعمل GitHub Actions عند فتح PR أو الدفع إلى `main` أو `hardening/docs-csp-ci`، وتفحص صياغة JavaScript وJSON وتتحقق من عدم رجوع سمات الأحداث المضمّنة. هذه فحوصات ساكنة وليست بديلًا عن اختبار الواجهة في متصفح حقيقي.
